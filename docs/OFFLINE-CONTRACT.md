# Offline Contract v1

The offline map pack — what the app downloads for offline use, where it is
stored, and how its one-time migration certifies itself — is defined HERE,
not by the app code. The app is built to satisfy this contract; the tests
derive their expectations from this contract (via the frozen fixture), never
from the app's own functions. A change to the pack is a change to this
contract: bump the version, regenerate the fixture in the same change, and
review the set diff (the freeze rule below).

Adopted 2026-11-04 (architecture Phase 5, candidate C4). At adoption the
contract was verified against the app as shipped in Beta 1.102: a fixture
generated from this document's rules matched the app's own
`preloadUrlList()` output EXACTLY (same 897 URLs, same order, same
fingerprint) — the generation gate recorded in the Phase 5 register entry.
From that day the fixture is the truth and the app must match IT.

## The pack set

The pack is a SET of URLs, constructed as follows. Two embedded basemap
styles (day and night, `parts/pmstyles.js`) contribute, in day-then-night
order:

1. **Sprite files — 4 per style.** The style's sprite base URL with the
   suffixes `.json`, `.png`, `@2x.json`, `@2x.png`.
2. **Glyph files — 256 per style.** The style's glyphs URL template with
   `{fontstack}` replaced by `Noto Sans Regular` and `{range}` replaced by
   `a*256-(a*256+255)` for a = 0..255.
3. **Vector tiles.** For each vector source in the style (today: one source,
   tile template
   `https://tiles.basemaps.cartocdn.com/v/20261026-01/vectortiles/carto.streets/v2/{z}/{x}/{y}.mvt`,
   maxzoom 15):
   - **Wide-area pass:** every tile covering the Vaughan box
     `{ w: -79.75, s: 43.70, e: -79.35, n: 44.05 }` at every zoom
     z = 8..min(14, source maxzoom). Tile numbers are the standard
     slippy-map numbers (x from longitude, y from latitude via the Mercator
     formula); the north edge gives the smaller y.
   - **Route-core pass:** if the source maxzoom is 15 or more, every z15
     tile covering the route box expanded by 0.005° of longitude and
     0.004° of latitude on each side. The route box is the bounding box of
     the route's street geometry (ROADS in `parts/data.js`) — the same box
     the app computes as `routeBox`. (Verified at adoption: including the
     REFERENCE features would move the north edge from 43.8226209 to
     43.8241078, which lands in the same z15 tile rows; the set is 15 tiles
     either way.)

Duplicate URLs across styles/passes collapse (the two styles share one
tile source). **The resulting set has 897 URLs** (633 tiles + 256 glyph
ranges + 8 sprite files).

The frozen set lives in `tests/browser/fixtures/offline-pack.json`
(`{ contract: 1, count, fingerprint, urls[] }`, construction order),
generated by `tests/browser/gen-offline-fixture.mjs`, which implements the
rules above from these constants plus the route data — never by calling
the app.

## Multi-route packs (Beta 1.117 F5; this section added Beta 1.170)

The set above is the pack for the shipped route (Route 5W). Since Beta
1.117 the app's manifest (`preloadUrlList()`) is the UNION over every
known route pack: the shared chrome (the two styles' sprites and glyphs,
exactly as above) once, plus each pack's own tiles — its offline-area box
(a pack without one falls back to its roads' bounds) at z8–14, plus its
z15 route core. With Route 5W the only pack present, the union IS the v1
set above, byte-for-byte and in order — `selftest-nv1152` pins that
equality against the frozen fixture, and the freeze rule below still
governs the base set.

Each pack's tile enumeration is budgeted at **PACK_TILES_MAX = 20000**
tile iterations per pack (Beta 1.152 NV3b): each zoom's span is counted
before its loop runs, and a zoom that does not fit the remaining budget
is skipped whole. Under the budget the output is identical to the
unbudgeted enumeration. Each route's preload record counts that route's
saves against its own tile list (`routeSaved` / `routeTotal`); the union
record counts against the union.

## Caches

| Cache | Role |
|---|---|
| `snowroute-offline-v1` | The downloaded pack — exactly the set above, or the multi-route union when created routes are present. Served FIRST for map data; never evicted by browsing. |
| `snowroute-tiles-v1` | Ordinary browsing tile cache. FIFO eviction at **MAX_TILES = 3000** entries. |
| `snowroute-shell-v1` | The app shell (page + integrity-checked library files). |

## The migration flag

- Key: `snowroute.v5.packmig`.
- Value: the fingerprint of the pack list — `v1:<count>:<base36>`, where
  the hash is djb2 over the newline-joined list in construction order
  (`h = ((h << 5) - h + charCode) | 0` per character), rendered unsigned
  base36. For v1 as adopted: **`v1:897:mm56ak`**. The flag always
  certifies the exact list it was earned on: with created routes present
  the list is the multi-route union, so the count and hash in the stored
  value grow with it, and a styles or pack change that moves the list
  moves the fingerprint and re-runs the full pass (Beta 1.96).
- The flag is set ONLY after a verified full pass: every manifest URL
  that exists in either cache is present in the pack cache (the migration
  copies missing entries from the browsing cache and prunes non-manifest
  entries from the pack cache). A failed copy leaves the flag unset and
  the migration retries on a later boot. A download that saves the full
  set earns the same flag directly.
- With the flag matching and the pack census equal to the manifest count,
  the migration takes its fast path (no per-file sweep).

## The freeze rule

The fixture changes ONLY under a contract version bump, in the same change
as the contract edit, with the set diff (added/removed URLs and the count
change) reviewed and recorded. `tests/browser/selftest-offline-fixture.mjs`
(CI build-and-test) re-runs the generator and fails on any byte difference
from the frozen fixture, so an accidental regeneration — or a route-data /
style change that silently moves the set — fails the build instead of
drifting the tests. `tests/browser/selftest-sw-contract.mjs` pins the
service worker's cache-name and MAX_TILES literals to this document's
values.
